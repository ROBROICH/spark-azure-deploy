# Local Development Scripts

Use the root Poe tasks when possible so commands are discoverable:

- `uv run poe create-secrets` creates a private `.env` with shared local secrets.
- `uv run poe process-compose` starts the native service stack from `process-compose.yaml`.

## Security Scan

`security_scan.sh` uses `TRIVY_IGNORE_FILE` when it points to an existing Trivy ignore file. If the default ignore file is absent, the scan continues without `--ignorefile`.

## First Local Setup

1. Run `uv run poe create-secrets` if `.env` does not exist yet.
2. Start shared infrastructure with `docker compose --env-file .env up --wait`.
3. Start services and the frontend with `uv run poe process-compose`.

If `.env` is regenerated, remove the existing Docker containers and volumes before starting again. Postgres, MinIO, Temporal, and SpiceDB persist credentials and will reject newly generated secrets against old volumes.

The only bundled database seed is `scripts/data/gesetze-normen-seed.sql.gz` (deconstructed German norms for the gesetze-normen database). Postgres loads it automatically on first initialization of a fresh volume; the data cannot be regenerated by users, which is why it ships with the repository. All other databases start empty and are migrated and seeded by the services themselves.

Process Compose loads the root `.env` by default and injects those values into managed processes. Keep generated `.env` limited to shared local secrets and external provider credentials. Application-specific settings stay in each service's tracked `.env.local`; `process-compose.yaml` should only add local runtime wiring and explicit aliases where a service expects a different environment variable name.

Do not generate nested `__` variables in `.env`. Services that require names such as `TEMPORAL__S3_ACCESS_KEY_ID` or `DB__PASSWORD` get those aliases explicitly in `process-compose.yaml`.

`create-secrets` asks for the email and password of the local Keycloak login user, an OpenAI-compatible LiteLLM base URL, API key, chat model, embedding model, and a Docling endpoint. It does not bake in project-internal endpoints. Leave the Docling OAuth fields empty when your Docling deployment does not require OAuth.

The login user is written to `.env` as `LOCAL_USER_*` and seeded into the local Keycloak realm by the `keycloak-bootstrap` container. The `oauth2-proxy` container serves the frontend on `http://localhost:3000` and enforces the Keycloak email/password login before proxying to the Vite dev server on port 3002.

The protocol service already supports separate source database credentials through its `PROJECT_LOGIC_DB_*`, `FORMAL_COMPLETENESS_DB_*`, `COMMENT_DB_*`, `SUPPLEMENTARY_DB_*`, `PLAUSIBILITY_DB_*`, `DOCUMENT_MANAGEMENT_DB_*`, `ADMINISTRATIVE_DRAFT_DB_*`, `EXAMINATION_DB_*`, and `OBJECTIONS_MANAGEMENT_DB_*` settings. The generated local `.env` only writes `DB_PASSWORD`; add source-specific protocol DB variables manually when a deployment uses different credentials per database.

`create-secrets` writes both host-style Docling settings used by `modul-inhaltsextraktion` (`DOCLING_HOST`, `DOCLING_PORT`, `DOCLING_PROTOCOL`) and URL-style Docling settings used by the legal-reference worker (`DOCLING_BASE_URL`). The Docling OAuth settings (`DOCLING_TOKEN_URL`, `DOCLING_CLIENT_ID`, `DOCLING_CLIENT_SECRET`) are only written when Docling requires OAuth; empty values would fail URL validation in the workers. Existing `.env` files created before this branch need those keys added manually.

## Process Compose

Every Python command runs through `uv run --locked --all-packages`, so workspace packages are available and the lockfile cannot change during startup. FastAPI services run with `uvicorn --reload`.

The seed processes are one-shot dependencies of the frontend:

- `project-logic-seed` inserts the default status and project type rows required by the create-Verfahren dialog.
- `formal-completeness-seed` inserts FCS template categories and document types for the default project type.
- `administrative-file-draft-seed` inserts the default VAE template from `src/scripts/data/vae_nodes.json`.

The `frontend` process provides local Vite proxy endpoints and receives the local user identity from the root `.env` (`LOCAL_USER_*`), matching the user seeded into Keycloak. A frontend `.env.local` is still useful for personal overrides, but it is not required for `process-compose up`.

To start one service and its dependencies through Process Compose, use:

```sh
process-compose run frontend
```
